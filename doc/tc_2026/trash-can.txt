A well designed collection and actuation system is desired to maintain the timing correctness and to not mislead a system control decision by tainting the acquired samples. Thus,  requiring a low intrusion to achieve a smother sampling process that does not affect neither performance nor energy.
Moreover, when dealing with dynamic frequency control in a real-time system, timing correctness is the key threshold for actuation, thus taking into consideration the performance impact of frequency reductions is necessary to build awareness of possibilities to further optimize energy-savings, and most important to restrict reductions whenever a impacting resource sharing contentions is detected, which would incur in a greater performance loss, as some stalls can have way more impact when the CPU is running slower. Furthermore, such works do not account for tasks migration, which can be used to both balance the actual task-set load at run-time, avoiding temperature hot spots [ref-to-dark-silicon-law], and by avoiding resource share contention (e.g., sequential execution instead of parallel).

In this paper, we present an \gls{ANN}-based \gls{DVFS} and task migration heuristic for multicore Real-Time Embedded Systems. The most representative counters are used as inputs to a \gls{ANN} that is used at runtime to predict the impact of power-saving operations on tasks. The \gls{ANN} is subjected to both, online and offline learning. Moreover, our implementation focuses at a well design monitoring and actuation system to achieve low intrusion at run-time.

The actuation heuristic is composed of two main phases: one periodically executed inside a hyper-period and one at the end of a hyper-period. An hyper-period is defined as follows: \{$\forall t \in T_{CPU_i}: HP_{CPU_i} = LCM(HP_{CPU_i},t.period)$\}, where $LCM$ is the least common multiplier function, $t$ is a Task, $T_{CPU_i}$ is the set of tasks of the ith CPU $CPU_i$, and the $HP_{CPU_i}$ is the accumulated hyper-period of the ith CPU, which starts with the value $1$. Moreover, the periodic phase activation can be reconfigured as needed, pondering actuation response time and overhead. In our implementation we assumed the periodic actuation to be executed at every 10 milliseconds, using the very-own PEDF scheduler time-slicer interruptions to avoid additional overhead.

The first phase, which is executed at each 10~$ms$s, runs the \gls{ANN} model for \gls{DVFS} control. As a 10~$ms$ performance trace usually does not account for all tasks trace within a CPU, applying a frequency decrease at this moment can be considered unsafe. Thus, the main purpose of this phase is to rapidly actuate predicting performance losses and increasing the CPU frequency as needed. Moreover, every task must store the \gls{ANN} inputs and outputs for continuous learning at the second phase.

The second phase, which is executed at the end of a hyper-period, works like a voting system for both intra-CPU scope and inter-CPU scope. For the intra-CPU scope, the heuristic will evaluate the possibility of downgrading its frequency, which will only happen if every \gls{ANN} result of its respective tasks were decrease actions. \todo{The training can be done as follows: If the CPU idle time percentage is greater than a threshold, the decrease action will be chosen. In the worst case, if a deadline miss occurs, the increase action is selected. In both cases, the \gls{ANN} must be fatherly trained by backpropagating the respective errors for the collected inputs and outputs.} Following, the inter-CPU scope is composed of the voting for the frequency decrease in the cluster, which will be executed if, and only if, every CPU in the cluster agrees with a frequency decrease. Moreover, when the voting is done, an imbalance check is executed, using the frequency as an imbalance metric for inter-Clusters and the CPUs' idle time percentage for intra-cluster. Thus, according to a user-defined threshold, if an imbalance is detected, the migration algorithm is triggered as follows: first, a load balance algorithm, which is out of the scope of this paper, but could be thought of as \textit{bin packing}, is used to achieve the balance between CPUs load. If the task allocation has changed, the current highest frequency between CPUs is selected, which will be optimized in the next heuristic iterations. Otherwise, the task-set is set as imbalanced and no further tries of load balance will be executed till the task-set changes. A flow diagram representation of the heuristic is depicted in Figure~\cite{fig:heuristic2}.

% Intro to ANN and why using it
\gls{ANN}s applies the principle of function approximation by example~\cite{Pagani:TCDICS:2020}, meaning that they learn a function through an input-output pair, also called labeled input, thus it is considered a Supervised learning approach.
Moreover, \gls{ANN}s can be used to exploit unknown functions, where we only have access to past examples and want to predict the next behavior based on this experience. Its internal structures (e.g. hidden layer neurons) interact through connections and activation functions applied to the input to determine the strength of an output neuron, usually represented in the range \{0,1\} or \{-1,1\}. Supervised learning techniques are not limited to a linear approximation and their capability of model extrapolation to correctly classify unforeseen scenarios in a reasonable manner~\cite{Pagani:TCDICS:2020} supports adaptability in a learning scenario.

% Comparison to unsupervised and reinforcement learning
Other methods like unsupervised learning (e.g. k-means), are focused on describing a hidden structure for unlabeled data, which does not fit our scope, as we want to extrapolate the relation of performance counters, usage and performance issues. Reinforcement Learning (e.g. Q-Learning) techniques, on the other hand, learn a state-action mapping through trial-and-error to achieve the best actions in each state. However, an important issue in reinforcement learning is exploration versus exploitation (i.e. getting stuck in a suboptimal solution). Moreover, a trial-and-error solution for critical systems must be cautious to avoid timing issues. In~\cite{Rai:ICCI:2009}, authors shown that \gls{ANN} outperformed linear regression method when predicting shared level 2 behavior, and shown similar performance to model trees, Moreover, \gls{NN} has already been proven to provide satisfactory results when used for performance prediction, and \gls{DVFS} and \gls{DPM} control~\cite{Chen:SENSORS:2018,RongYe:ASPDAC:2012,Shen:ACMTDAES:2013,Marinakis:ESL:2019}, however, not considering performance losses. Thus, \gls{ANN} learning is a suitable solution for a noisy data-set like performance counters (high variability of multicore architectures) and exploitation of new scenarios, providing a certain level of adaptation, even when considering offline learning only. In this work we aim at both online learning and offline learning, where offline learning provides a initial broader knowledge while online continuous learning provides a better optimization for the running task-set and accounts for model adaptation.

\subsection{Migration Heuristic}\label{sec:migrationv2}
\vtwo{Following the same principle of describing the system performance through the selected performance counters, we designed a migration heuristic that focuses on minimizing the activity variance between CPUs. In this way, we enabled the migrations over the concept of a weighted activity vector. The heuristic adjusts the feature weights $W_i$ online following a linear regression estimation of the composed activity per CPU, shaping the heuristic for the current task-set at every actuation step. Moreover, every counter is also weighted by the task utilization, thus, providing a limit of $1*W_i$ for each activity measure.

We evaluate the possible migrations into single steps, where one CPU sends one task to another or considering a swap between two CPUS. First, the system evaluates the possibilities, scoring the migrations according to its effectiveness. Moreover, an actuation is only allowed if it meets the usage restrictions and if its performance is higher than a minimal improvement threshold. If no simple migration fits the requirements, the heuristic attempts a task swap.
Before the execution of the migration, a reset of CPU frequency takes place, setting it to the maximum value, preventing that a migration exceeds the Safety Margin established (e.g., due to an underestimation of the migration impact). In this way, we provide enough information for the linear regression to learn, readjusting the activity weights accordingly. This integration of the migration heuristic and the energy-optimizer prediction model is the key-step to not only increase the reliability of the activity vector representation but also to provide more training phases for the very-own \gls{ANN} model.
